# Ownership and source preservation

`specification.ts` owns declared specification family/version, the applicable
schema dialect and document capabilities. Core presentation reads the captured
typed `SpecificationContext`; `info.version` is unrelated. OpenAPI 3.0 uses the
restricted OAS evaluator and exact Draft 4 boolean-bound handlers, alongside its
dated structural artifact and normative relationship checks. Its Schema Object
references ignore siblings; modern schema references retain applicator semantics.
Ordinary declaration edits invalidate captured semantics and never migrate files.
The [implementation record](implementation/native-openapi-support.md) tracks
family-specific coverage and qualification, including work still incomplete.

`schema_value_forms.ts` supplies native field shape choices from the canonical
occurrence's family and selected dialect. Core decodes that typed metadata; it
does not choose schema semantics. Metadata-bound field proposals capture the
existing complete object snapshot and recheck its field forms in the engine
before publishing a CST edit. `schema_authoring_context.ts` owns the occurrence,
root/resource declarations, family, selected dialect and base identity shared by
field forms and type choices. Field metadata also binds the keyword; equal
shape lists cannot transfer a pending action across contexts or fields. Core
decodes the same context, and native refresh compares it before opening the
existing reviewed editor. Sequential proposal actions recheck the current graph.
Unknown dialects supply no assumed forms. Before applying a metadata-bound
schema edit, Core refreshes all captured nonbundled inputs through the existing
anchored disk reader, then rechecks generations, identities, approvals, conflicts
and cancellation. Watcher delivery cannot authorize a stale proposal; dirty
working buffers retain their content when an external conflict blocks it.
`swagger_schema_artifact.ts` binds the pinned Swagger artifact for both
structural and schema-meta validation. It removes only the tuple-items minimum
absent from the referenced Draft 4 text, preserving other array and flat-object
restrictions without modifying the vendored schema.

External Example Object locators are discovered from canonical graph scopes by
`external_examples.ts`; acquisition remains in Core's existing approved
`ProjectAccess` capture. `CapturedExternalExample` retains opaque bytes and their
content/physical/alias/generation ownership alongside parsed contract resources.
`AnalysisSnapshot` hashes both roles; external payloads are never dependency
contract documents. Data dependency monitoring and file history retain that
separation. Serialized media evaluation consumes captured wire bytes through the
same media/form/schema owners as HTTP, with the defining Example's source
location. Refactoring, migration, package publication and request/mock startup
retain captured-input freshness checks. Historical response inspection keeps its
original capture. Resource packages store payload bytes separately and load them
only through their approved package-directory capability. Unknown interpretation
is an explicit incomplete result, not success or a new filesystem/network loader.

`MigrationExamples` retains original Example
locations through the existing CST provenance map. It publishes byte copies
alongside contract outputs through the same atomic directory writer, with local
URI routes for cold acquisition. Core verifies each copy against the captured
snapshot before exposing typed review records; GUI and CLI list exact copied
resources. Target evaluation consumes only the delivered byte set.

## Explicit acquisition and CI reports

`ProjectImporter` owns a bounded immutable acquisition and a held output-parent capability. Local reads and directory enumeration use `ProjectAccess`; URL dependencies are requested only from the existing canonical graph and require exact-URL approval. Credential-free GET acquisition uses the native HTTP transport's overall deadline/cancellation owner and verifies every redirect before connecting. Original bytes and retrieval mappings remain separate from derived bundles. Clone uses the trusted Git runner with isolated configuration, no hooks/filters/submodules or dependency installation. `ProjectImportPlan` reviews a captured file set and publishes only to a new directory through `AtomicDirectoryWriter`; source, foreign destinations and cancelled stages remain intact. Before a URL-import plan becomes publishable, its generated manifest passes the same bounded key/mapping reader used on reopen, including the root mapping, URI/path normalization and manifest byte limit. A complete acquired graph alone does not certify a readable project. Opening is separate from publication. The small native controller binds completion to its original workspace/navigation owner and disposes/cancels independently of the workspace's canonical buffers.

`CiReports` converts existing diagnostic and contract-test records rather than adding a diagnostic authority. SARIF keeps producer/version, original file identities, UTF-16 offsets and captured line/column ranges where available; no working-file reread or staging-file substitution is allowed. Incomplete runs retain unsuccessful invocations even with no findings. JUnit contains only actual selected cases and measured execution duration; assertion failures differ from operational/incomplete errors, while untested operations remain coverage metadata. Duration and operational-failure classification are retained in typed core case records for JUnit without changing version-1 test JSON. Explicit report files use the existing private staged no-clobber writer. Known supplied credentials are redacted before serialization; this is not a claim to detect every possible secret in arbitrary user prose.

## Execution boundaries

Request, OAuth, mock, test, Git comparison, and semantic-review work starts from an immutable `ExecutionPlan`/`AnalysisSnapshot`. The plan records project ownership, root and operation identity, original resources, source/configuration revisions, non-secret environment selection, and exact tool identity. Drafts are separate from `BufferStore`; only the explicit reviewed example transaction enters source history. Project closure, replacement, cancellation, or a stale owner invalidates asynchronous secret, token, transport, and tool completions before they can update presentation.

The TypeScript engine remains the contract interpreter. Its operation projection preserves inherited and local parameters, servers, security alternatives, media types, exact CST values, and physical source locations. Dart core serializes those captured semantics onto a single native HTTP/TLS path shared by Try and contract tests, and validates both outgoing and received data through the existing evaluator. Responses retain bounded raw bytes independently of display truncation. Cross-origin redirects require a new authorization decision; credentials and authenticated bodies are not replayed. OAuth uses an external browser, one-use state and PKCE S256 with a loopback-only callback. The native Secret Service channel accepts only BusyAPI-scoped opaque keys; renderer messages and contract text cannot name arbitrary keyring entries.

Request and response content selection uses the most specific matching declaration without reordering authored content; parameter names and charset compare case-insensitively while other parameter values retain their defined case. Query serialization encodes data before inserting form-list commas. Relative OAuth authorization/token URLs resolve against the selected effective Server URL, including the existing environment override and variables; absolute authorization-server URLs remain absolute. OAuth Basic client credentials are individually form-encoded before Base64, separately from API HTTP Basic authentication. Stale or cancelled owners cannot begin a delayed token exchange. A retained no-authentication selection is available only when effective requirements permit it; newly inherited requirements require a current choice, while an explicit operation-level empty security array permits clearing without discarding input.

Conformance completeness includes applicable body/header checks that were skipped because a codec or existing bound was unavailable. Such cases cannot pass contract tests, history, CLI JSON or JUnit as complete. JSON runtime instances use the existing strict JSON CST parser even under an unconstrained schema; parser-limit exhaustion is incomplete rather than malformed-instance invalidity. Response headers retain schema/content/style/explode metadata. Bounded representation inspection follows canonical references, composition and modern tuple positions; primitive alternatives, flat arrays/objects and JSON content feed exact lexemes to the original complete schema evaluator. The documented primitive-conversion policy permits a completely checked valid interpretation to prove wire conformance, without claiming a unique data type. Exhaustion without a proof, undefined nested serialization and unsupported codecs remain incomplete. Direct requests, saved cases and mock responses submit the original captured header occurrence to this shared owner. Content-Type header declarations are ignored as specified, independently of actual media selection. Set-Cookie field lines are never blindly comma-combined; the 3.2 exploded-object representation remains distinct from unsupported 3.1 composite interpretations.

Additional-operation tokens retain case in projection, selection, saved cases, labels, preparation and transmission. A dedicated connection adapter replaces only the SDK's neutral request-method prefix with the captured token; URI, header and body bytes retain their existing owners. Native TLS keeps trust, hostname and client-certificate checks, with the same raw socket available for cancellation during its handshake. The shared request builder and final transport boundary refuse exact uppercase TRACE content and sensitive fields before connecting or acquiring HTTP credentials (RFC 9110 §§9.1,9.3.8). Lowercase custom `trace` retains its separate identity; mutual TLS does not become an HTTP credential field.

Mocks are a foreground child of one captured plan. A small packaged Node entry uses Prism's supported public server/operation APIs against BusyAPI's already-resolved in-memory document, while a CST overlay supplies exact authored JSON example bytes bound to Prism’s selected operation, response, media and example. The overlay verifies the projected value before reusing its original lexemes; dynamic and proxy responses retain their own bytes. It binds loopback, reports actual readiness/port, and dies with cancellation/project/app shutdown. Ordinary mock mode never forwards upstream. A distinct user action can start Prism's validation-proxy configuration against one explicit credential-free HTTP(S) base; that mode validates both directions and cannot arise from opening, selection, or ordinary Start Mock. Editing any captured dependency only marks the run outdated. Contract tests select declared cases and reuse the request builder, transport, and evaluator; unselected operations remain explicitly untested.

Git logic is headless and invokes one trusted executable with fixed argument arrays and machine-readable output. Read-only repository discovery/status/diff does not authorize hooks, filters, or helpers; explicit trusted mutations use Git's normal workflow. Historical input is read from resolved commit objects without checkout mutation and is never completed from current disk files. The historical manifest’s root retrieval aliases are attached before initial analysis, just as for dependencies; schema identity and 3.2 $self remain separate. oasdiff receives two separately coherent snapshots and is a compatibility classifier, not a validity authority. Its native model retains raw source diff, locations, rule/severity, source ownership, and unsupported dynamic-reference/reusable-Path-Item coverage.

A Git file review captures its repository owner, literal path, working-tree or index mode, raw file bytes/mode, complete bounded index, HEAD/branch and the exact diff inputs. Trusted reviews apply Git normalization/clean filters once into private object storage; the displayed normalized bytes are the bytes later staged. With `core.fileMode=true`, executable mode follows Git’s owner-execute bit; group/other execute bits alone do not change it. Staging revalidates the review, holds the ordinary exclusive index lock, updates a copied private index with captured blobs and atomically publishes it. Later worktree writes cannot change the accepted blob, and unrelated index entries remain captured. A saved dirty buffer or newly trusted normalization requires another displayed review before Stage. Branch rows use refreshed status; retired or superseded dialog/review completions cannot publish state.

HTTP gzip decoding retains the SDK codec and CRC validation. A bounded received-only framing pass verifies every gzip header, DEFLATE block boundary and member trailer/ISIZE on a private worker without appending input or producing decoded bytes. It reads fixed-size buffers and shares the existing decoded bound; the HTTP lifetime kills and awaits its worker on timeout/cancellation. Valid concatenated members remain supported, including empty members. Received bytes are split at possible member headers to avoid the pinned SDK streaming boundary defect; the independently counted decoded size must match the codec output. Query API-key ownership checks decode only raw query names; redirect redaction decodes only values belonging to selected secret names. Redirect summaries retain literal matching and use bounded iterative byte matching with prefix fallback for escaped/mixed spellings and query spaces. Original URI spans are replaced; unrelated percent-encoded bytes are never decoded as document text. Unrelated raw values retain their serialization.

The oasdiff input remains the graph-proved exact single-file derivation. Its narrow consumer adapter rewrites only an entry-resource `$ref` whose target is already an embedded identified schema to the equivalent local component pointer, then reruns the graph proof; it does not remove `$id`, flatten schemas, rewrite anchors/dynamic references, or read an original filesystem path. oasdiff's structured additions and authentication/response sections are presented conservatively beside its confirmed breaking rules instead of being hidden in raw JSON.

The desktop composes these services into compact Try, Mock, and Git/semantic-review surfaces without adding a permanent pane. The compiled CLI calls the same core plans and adapters using saved inputs. Documentation WebKit remains read-only and has neither credential nor native-network APIs; adding application `network`/`network-bind` permissions does not expand the renderer message boundary. Strict Snap Secret Service persistence is conditional on the manually connected `password-manager-service` interface, with explicit session-only behavior when unavailable.

## Governance code review and restriction boundary

`inspectPolicyCode` parses bounded captured JavaScript through pinned Acorn, returning literal import/require candidates and UTF-16 ranges without executing code, accessing files or doing package resolution. Computed loads and syntax errors remain explicitly incomplete. Literal inspection is not proof of every possible JavaScript load: execution must enforce an approved immutable closure and retain denied attempts even when project code catches them. Code syntax is separate from the canonical OpenAPI graph, which still owns all contract/reference interpretation. Governance projections use the same whole-Reference-Object boundary as that graph, so ignored callback siblings cannot create policy operations.

The dedicated native restriction target has two process-local stages (native profile **2**). The single-threaded launcher installs Landlock **before exec of Node**, so all subsequently created Node/libuv threads inherit it. The bootstrap read grants are the fixed installed worker directory, exact pinned Node executable, exact already-mapped loader/runtime DSOs, `/etc/ld.so.cache`, `/dev/null` and directory-listing-only `/proc/self/fd`. There are no write grants; only Node and trusted mapped ELF files have execute grants. Explicit compatibility DSOs are loaded before enumerating mappings. Ambient OpenSSL configuration/provider loading is disabled with the pinned runtime's `--openssl-config=/dev/null`; startup inherits no project/environment options. The inherited startup seccomp gate denies io_uring and all socket creation/transport.

The launcher pins its own proc-FD directory inode with exactly one inherited **O_PATH** descriptor. Without that pin, procfs inode recreation can make the same Landlock pathname grant stop matching after exec, causing an intermittent inspection denial. The addon requires the pin's exact own-process target, matching directory device/inode and O_PATH-only flags, consumes it while its inspection listing still holds the inode, and closes both before captured code. Missing, substituted or duplicate pins fail closed; no arbitrary directory capability is admitted. This is identity retention, not a broader procfs grant, skipped inspection, process retry or security fallback.

After trusted bootstrap, the Node-API target rejects inherited descriptors and nonempty file-capability requests, adds an empty main-thread Landlock layer, and installs **seccomp TSYNC** over every existing thread. Its default-deny allowlist excludes **all file-open/reopen APIs**, including reads of the trusted bootstrap assets. Thus older Landlock does not need to synchronize an additional read policy across existing threads: no thread can acquire a file descriptor after the seal. Previously captured project modules are supplied only by the immutable memory loader. Socket families, process/thread creation, metadata mutation, ptrace/process-memory, io_uring and executable file mapping stay denied. Existing libuv asynchronous work/timers, V8 anonymous memory and scoped self-signals remain usable. Metadata queries are not file-content permission. CPU/file/descriptor/core-dump limits and parent-death termination complement bounded wall/output ownership and awaited exit. Failure at either stage exits before project-code evaluation. This is not an ABI-check-only downgrade: pre-exec inheritance plus the all-thread file-open seal replaces ABI-8 Landlock TSYNC. The minimum is ABI **3**, covering REFER/TRUNCATE; later socket/scoping/ioctl rights are independently denied by seccomp. See [Linux 6.8 Landlock inheritance](https://docs.kernel.org/6.8/userspace-api/landlock.html#inheritance) and [libseccomp TSYNC](https://github.com/seccomp/libseccomp/blob/v2.5.5/doc/man/man3/seccomp_attr_set.3).

Provision declarations explicitly with `python3 tools/prepare_policy_isolation.py --node-include /path/to/node24/include/node --seccomp-include /path/to/extracted-libseccomp-dev/usr/include`. They are cached under `build/`, never installed as a new toolchain. Normal offline contract preparation/CMake installs the dedicated helper, native guard, startup gate and matching receipt in every build mode. A missing stage has no ordinary-Worker fallback. The fixed bundled-library path is the only startup environment setting; the trusted entry clears it before project code. Runtime isolation requires enabled Landlock ABI 3 and libseccomp 2.5.5 or newer, plus successful actual restriction/TSYNC installation.

`reviewPolicyCode` consumes canonical policy declarations and the maintained enhanced-resolve 5.26.0 public API over an immutable virtual filesystem. The core acquires metadata/content requests through its existing anchored access and URI mappings. Missing, denied and excluded ambient parent/global-module paths are distinct; no loader reads project paths or the network. Package exports/imports, selected targets, formats and literal dependencies retain their original identities and source ranges. V8's non-invoked CommonJS wrapper compilation determines ambiguous module syntax; Acorn supplies dependency locations. Module inspection is not a claim to discover computed loads: these stay incomplete until their closure can be proved.

`PolicyCodeReview` retains source generations and negative/directory observations for freshness, separately from the reusable code identity. Explicit `PolicyCodeApproval` binds the code/dependency snapshot, installed helper/native profile and selected project/root for one run. It is consumed once, never persisted in a project, lock or display preferences. Before/after execution the core rechecks bytes, generations, mappings, lookup metadata and runtime identity. Metadata/type monitoring catches new package candidates as well as changed unopened helper source.

Approved execution uses a disposable `PolicyProcessWorker`, not a thread presented as a sandbox. The dispatcher reserves the background slot and waits for real exit and complete bounded output; cancellation and owner death terminate the child. After both native stages succeed, Node's supported synchronous module hooks supply only reviewed sources/bindings, with no filesystem resolver fallback. The authentic CommonJS loader supplies normal CJS/ESM interop on demand; no eager closure execution, rewritten vendor runtime or require interpreter is used. Pinned bundled Spectral APIs are explicit review bindings. Unreviewed runtime loads remain incomplete even if caught by project code. JavaScript rulesets use whole-source provenance rather than invented JSON positions. Computed/unknown dependency closures and unsupported code formats still fail closed; ordinary declarative lint remains useful without approval.

Project JSONPath filters and custom format functions require the same explicit one-run review, even when a declarative selector has no JavaScript module dependencies. A conservative Acorn token admission check permits ordinary literal navigation without executing project expressions; Spectral still owns JSONPath and alias semantics. Approved format functions are awaited against the authored snapshot, retain their public format identities and fail incomplete on exceptions or invalid results. Off-severity rule functions are not invoked unless a source-pointer override enables their scope; explicitly approved module initialization is separate from rule invocation. Exact-CST numeric proofs guard custom inputs/options, public full-document/inventory/rule-data reads, JSON modules and executable selectors/formats. The IEEE-754 witness admits exactly represented fractions and integers, not decimal round-trip guesses. An unsafe read stays incomplete even if a function catches the denial; safe narrow functions need not inspect unrelated large examples. These guards never replace, serialize or normalize canonical source values.

`python3 tools/test_policy_isolation.py` runs controlled real-kernel, process-lifetime and actual reviewed-governance cases, compiling its syscall-attempt helper only in a temporary directory. Kernel, native application, packaging and performance checks establish separate acceptance criteria.

## Physical file intents

`planFileMove` uses the canonical graph, immutable configured-root snapshots and existing source CST. Temporary typed-occurrence seeds come only from captured graph positions; final graph and cold-retrieval proofs use ordinary closure. Physical locators, relative authored schema identifiers and manifest root paths are reviewed edits. Description URIs retain the graph occurrence's base, including OAS 3.2 `$self`; Server URLs instead retain their original retrieval location, and OAuth endpoints remain Server-relative ([description URIs](https://spec.openapis.org/oas/v3.2.1.html#relative-references-in-api-description-uris), [API URLs](https://spec.openapis.org/oas/v3.2.1.html#relative-references-in-api-urls)). Filesystem paths in configuration are not URI-escaped reference strings. Payloads, exact numbers, unknown fields, source representation and unrelated bytes are not serialized through JS objects.

Typed URI occurrences are passive locations, not another resolver or acquisition queue. `Example.externalValue` consumers block file deletion and participate in move reviews without reading/parsing their serialized payloads. Physical-locator repairs preserve arbitrary authored fragments rather than interpreting them as JSON Pointers. A file also used as an external serialized example cannot undergo contract-text repairs that would change those example bytes; retaining its original URI context avoids that alteration where the graph proves it. Example payloads, extensions and ignored Reference Object siblings never become URI declarations merely because their keys match. The derived-bundle producer revision is `4`; its description/Server URI bases use the same graph-owned distinction.

An explicitly selected unused or example-only file is supplied separately as a captured opaque move source, never inserted into API graph contexts based on payload keys. Its text/BOM remains unchanged; only established external-example locators and project mapping paths are repaired. The extra physical snapshot participates in generation/disk freshness, history, required-save grouping and the existing recoverable publication/archive boundary. The manifest itself is not an opaque contract move target. Moving a configured/extended governance input, or moving with an unavailable/incomplete policy footprint, is blocked rather than guessing policy-path repairs or executing code. Move and deletion reviews share read-only policy capture and freshness verification. Native preparation reports clean reloads to the still-current workspace, even when its requesting route has retired; a later project/selection cannot acquire the review.

File-move proofs retain one latest immutable graph keyed by owning context, occurrence-seeding mode and actual prepared-text revision. Unchanged references do not rebuild the entire graph repeatedly; actual edits invalidate that cache. Copied-URI and example-impact scans likewise reuse parsed documents until an edit changes their text. Caches do not introduce resource acquisition or retain an unbounded graph per root. `tools/benchmark_file_impact.cjs` separately measures synthetic snapshot capture, worker plans and result serialization over hundreds of resources; it is not native input/performance acceptance.

`BufferPathEdit` verifies URI/path, generation, expected text and BOM alongside every text edit. One history entry binds physical buffer objects to text and path states, including earlier Source history. A synchronous project-owned identity observer updates roots, file lists, approved mappings, dependency monitoring and snapshot revisions on Apply/Undo/Redo. `publishedPath` is disk ownership, not undo state: undo after Save stages a reverse move. The native workspace separately migrates root/resource selections, tabs, reading locations and fold state, invalidating retired async owners.

`BufferCreation` and `BufferPresenceEdit` extend that same transaction, not a second file writer. Active buffers remain separate from retained absent owners; hidden working text, BOM, selection and history survive deletion. `publishedPresent`, like `publishedPath`, is acknowledged disk ownership rather than undo state. All text/path/presence generations and destinations are checked before any buffer mutation. History ownership counts permit bounded retirement without scanning the whole history on each Source edit. Snapshot acquisition refuses a virtually removed resource instead of rereading its old disk file, including policy input collection. Exact previously captured generations remain immutable; a later virtual deletion makes them stale.

`planFileDeletion` consumes each configured root's canonical graph plus the same read-only policy acquisition/discovery operation used by lint. Configured/default/extended ruleset inputs, unavailable dependencies and newly appearing default rulesets participate in impact/freshness checks without invoking governance or project code. Required consumers and configured/session URI mappings block the entire operation. Policy acquisition uses the same captured saved/working resource mappings as the API graph, including relative ruleset dependencies resolved from their approved URI rather than the worker's directory. `planFileCreation` captures an explicitly empty approved local YAML/JSON destination; it never creates a manifest or injects source content. Whole-file removal/restoration transitions retain tabs and reading state without taking ownership from a later navigation.

Named roots are a source projection of the current manifest, including unsaved edits, undo/redo and external reloads. An explicitly opened standalone contract keeps its own scope even beside a manifest. Removing a declaration never deletes its contract/fragments or selects a different current root; the native picker offers a reviewed, one-step configuration transaction. Every configured API snapshot participates in consumer impact and freshness. A manifest explicitly used as schema or `externalValue` data has dual ownership: consumers that would lose/rebind their target (including shifted array pointers), unavailable graph analysis and serialized-data consumers block Apply with source locations. Unrelated definitions and literal payload keys do not. No consumer repair is optional or silently guessed. Normal Save/Discard/Cancel and publication/recovery own the later configuration write. This impact proof is not a claim that the APIs are valid or that consumers outside the supplied roots are known.

Policy dependency discovery has its own completeness record, distinct from executing rules. Pending resources, malformed declarations, cycles and opaque executable dependencies do not establish a complete footprint. Declaration work is bounded, URI resolution reuses the canonical graph's URI function, and parser safety limits remain unchanged. The core verifies completeness consistency and original supplied-resource ownership before using the record; crashed/malformed discovery cannot enable deletion. This read-only stage neither approves project code nor supplies the still-required custom-code execution sandbox. Ordinary Source and independently safe authoring remain available when a destructive review is blocked.

Version-2 file-publication journals freeze every required repair before project writes. A one-file save expands to the file intent's captured participants, not unrelated dirty buffers. The core publishes new destinations with no-replace semantics, then required references/configuration, then archives old names through an anchored atomic no-replace rename. Archives are preallocated and journaled before removal. Presence fields distinguish creation, relocation and deletion; deletion receipts also retain the captured unsaved working copy separately from the original disk archive. Receipts describe per-file outcomes; they do not claim global filesystem atomicity. Restart inspection recognizes receipt gaps from actual bytes, checks live ownership, and never replays writes automatically. Whole-group recovery restores active/absent buffers and preserves newer external versions as conflicts. A matching earlier working-copy checkpoint can be adopted without overwriting the publication-recovered baseline or losing pending form input. Input or Undo during a frozen Save stages a later/inverse intent; acknowledging the earlier publication cannot discard it.

Directory durability is awaited on a dedicated Dart isolate, not the Flutter/UI isolate. Before scheduling, the existing Linux filesystem boundary pins the directory with a close-on-exec duplicate descriptor. The worker never resolves a path again; closing/reusing the caller's descriptor or replacing that path cannot retarget the synchronization. Completion and errors close the private descriptor before reaching the caller. File and directory synchronization remain required publication steps; moving the blocking syscall does not shorten storage latency or make an unfinished save successful.

Discard abandons only uncommitted intent. Already published files and original archives remain; frozen versions from an abandoned partial save remain in a private archive receipt. Root configuration is reconciled from its retained working manifest. A retired workspace releases live publication buffer references without removing durable intent. Ordinary single-buffer saving/recovery refuses an ungrouped file intent. The explicit retained-URI option writes a source-preserving `resourceMappings` entry in an existing manifest: physical identity changes while logical retrieval/base identity remains. The planner proves graph targets and actual schema evaluation in that retained context. It neither rewrites relative Markdown nor assumes another application's resolver reads BusyAPI configuration. Ordinary subsequent moves repair existing mapping paths. Native controls stage these same virtual transactions; widgets never own disk moves or publication.

Ordinary Save captures the actual buffer owner before publication. Its receipt acknowledges exactly the written generation against that retained object’s published path and disk identity, even if a later reviewed transaction moves or virtually deletes it. A replacement object at the old map key cannot inherit the receipt; later edits remain dirty.

Private view captures are frozen before asynchronous publication. Each workspace serializes them through the existing atomic private-state writer, retaining at most one in-flight write and one coalesced latest payload. Joined callers, including shutdown, await that durable drain; failures remain failures and permit a new capture/retry. No mutable later view state can change an already captured payload, and overlapping first writes cannot race on expected absence. This does not claim a cross-process lock or alter contract publication durability.

Acyclic internal references retain their original shared targets rather than expanding them or silently rebinding them to copied children. Review explains that the new inline value can still depend on those definitions. Actual cycles, reachable dynamic evaluation scope and duplicate identities remain refused. Structural refactoring directly on a literal-owned occurrence is refused rather than silently changing both meanings; the user can instead inline an ordinary API reference occurrence while retaining its original data-backed definition. Same-destination move no-ops remain byte-identical.

`planExtract` and `planInline` extend that same snapshot/review/history boundary. Reusable-family/destination metadata is shared with native object inspection. A bounded CST value-copy helper reindents only the copied fragment, retains structural YAML separators/final-newline state and proves exact values after reparsing, including large numbers and block-scalar clipping. Cross-resource moves of an authored `$id` spell its existing canonical identity explicitly rather than inventing one; inherited resource/dialect/dynamic changes still fail closed. The existing cold graph proof checks retrieval independently of an already warm resource set. Inlining leaves the definition unchanged, repairs copied relative references, separates Schema applicator siblings through `allOf`, and handles Reference Object overrides and Path Item overlap distinctly. An unchanged external definition can become unreachable after its final incoming occurrence is inlined; it is not deleted. Copied typed description URIs and Server templates retain their original meanings through bounded CST edits shown in the existing source review; equivalent authored spellings stay unchanged, opaque data fragments remain authored, and conflicting root interpretations fail closed. This shares graph bases/field metadata with bundling and file impacts, never fetches external examples, and leaves OAuth endpoints Server-relative. CommonMark links still require their separate rendering-context decision. Duplicate identities/dynamic scope, recursive expansion, ignored siblings and unproved URI/representation changes produce explicit errors with no plan. Each method has bounded edit/impact work and background worker affinity, so it cannot consume the sole foreground parser owner.

`planExtractToFile` composes the existing extraction and definition-relocation proofs over disposable immutable source texts. Other supported positions retain their legal named-component bindings. Temporary CST insertion slots never become authored wrappers, buffers or intermediate transactions. Canonical cold closure recollects newly reachable named bindings for every configured root before the second proof. The worker returns one final set of existing-source edits, one exact-value fragment creation and original-to-new semantic transitions. The core validates the destination/digest and combines them in the existing `FileCreationPlan`; no second writer, resolver or history exists. Native capture uses sequential small dialogs with complete teardown, captured draft restoration and one final source/usage review. Inferred creation restoration precedes relocation in history, so Undo relocates reading/selection ownership out before hiding the file. The source and new file remain one publication/recovery group, with new destinations published before incoming reference repairs. OAS-looking custom data that would change root interpretation is explicitly refused, not silently reclassified.

`planMoveDefinition` reuses that exact copy/graph proof. Where the source position permits references it keeps the original public component binding, including implicit security/discriminator names. Swagger 2.0 reusable parameter/response moves instead remove the original definition and repair captured consumers, with that distinction visible in review. Swagger security schemes cannot be externalized through standard references and report a located blocker; ordinary editing/rename remains available. Incoming whole-component spellings remain authored only when the binding is retained; descendant pointers and outgoing connections move together. Inherited discriminator wire names gain only a missing graph-proven mapping. A cross-resource Link `operationId` becomes an explicit `operationRef` to its uniquely captured operation, with mutual exclusion, comments and field-navigation transitions preserved. Conflicting root interpretations block the entire plan. Rebuilding a context retains its actual approved inputs and uses the existing cold graph closure for new dependencies, rather than injecting another entry's entire resource set. These are existing-buffer definition moves, not physical file operations.

Plain semantic transitions carry an optional destination resource as well as a pointer. Buffer undo/redo reverses both without changing physical file identity. The workspace maps object selection, active resource, occurrences, navigation history and private reading keys together. Schema expansion moving out of its old tree transfers to the new root; undo can merge it back into an existing ancestor tree without importing another tree’s scroll position. Intermediate retired Design pages cannot recreate pre-transition reading state. Captured extraction/move name/destination drafts resume through the same exact-source form restoration as other native forms.

The Hyperjump evaluation adapter revision `1.18.0+2` canonicalizes only graph-proven Schema `$ref`/`$dynamicRef` addresses in its disposable Document projection. Named dynamic anchors remain named for runtime evaluation; navigation candidates never choose the dynamic call stack. Multiple ordered pointer transitions preserve nested dependent-schema navigation across one history step and its reverse. Unfinished-key completion similarly repairs only an identified mapping hole and proves that mapping's syntax in an immutable hypothetical parse before returning one expected-text edit; it does not normalize an invalid document.

The exact JSON data reader's optional projection callback receives both a physical CST node and its current occurrence pointer. When entry data is also an established schema target, the bounded bundle adapter can retain its literal occurrence and place its schema interpretation at a separate legal Components destination within the same entry context. For a retained compound resource, un-identified schema roots must agree on their effective dialect. ## Input-method limitation

During active composition, scrolling can leave the input-method candidate popup
at its previous position until the next preedit update. Candidate repositioning
on scroll remains unresolved. BusyAPI uses the system input-method infrastructure.

Native Swagger 2.0 uses the same canonical graph, CST edits, headless core and
transport as the OpenAPI families. Its own root collections and restricted
Draft 4 Schema/Parameter/Items/Header models remain authoritative. Captured
execution projections retain source locations for native URL/media settings,
body/form parameters, response examples and security definitions; they are not
a converted editable OpenAPI 3.x document. See the native support record for
qualification status and explicit representation limitations.

Explicit migration is owned by the headless contract engine and core output
publication layer. It captures the same current buffers as other desktop
operations, retains source provenance during transformations, and validates
the target family. A migration review is independent of a declaration edit.
The core rechecks its captured buffers and disk inputs before atomic output
publication; live source is never a migration destination. Implementation
coverage and remaining blockers are recorded in the support matrix.
The [migration guide](migration.md) describes the desktop and CLI review flow.
